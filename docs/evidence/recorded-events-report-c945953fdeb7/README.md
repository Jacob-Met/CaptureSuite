# Recorded-event HTML report — source and original receiving

## Delivered behavior and current qualification

The new command creates a physically usable standalone HTML report from the
qualified CaptureSuite package reader. **The author’s eight focused cases and
the independent three-command Linux receiving passed. The original Mac browser
contract is incomplete at an observer keyboard-reopen step.** The original
exit-1 browser evidence remains intact; it does not establish a product defect
and is not presented as an all-C1–C5 pass.

Run from a supported checkout with Python >=3.12,<3.13:

```sh
python tools/report_recorded_events.py /absolute/recording.mmsession /absolute/new-report.html
```

The output parent must already exist, the output must be outside the source
package, and the output name must be new. The command does not create a directory
or overwrite a previous report. It renders the full UTF-8 result before opening
the new file exclusively, then completes write, flush, fsync and close before
reporting success. A failed write can leave a new partial file for inspection;
the operator guide documents that behavior.

The report includes complete returned checkpoint, annotation and sync-anchor
dictionaries in reader order, including unknown nested fields, large integers
and literal strings. It also includes exactly the reader’s seven normalized gap
fields. It does not recover omitted records, claim that normalized gaps contain
all raw fields, sort or align clocks, verify raw sensor streams, or infer that a
reader-reported finalized state proves a complete capture.

The report has no script or external resource. Its document, local section links,
native disclosures, inline light/dark/print styles and explicit coverage labels
work as a standalone HTML file. See the
[operator guide](../../design/research/RECORDED_EVENTS_REPORT.md) for the complete
reader/error/output boundary.
