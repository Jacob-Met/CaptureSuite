# Whole-session stream artifact identity

Issue 110 corrects a proven configuration-artifact collision in the radar export path. The actual simulator descriptors for sim.radar.1 and sim.radar.2 use streams sim.radar.1.frame and sim.radar.2.frame. Under the canonical sources/<source>/streams/<stream>/ layout, the legacy hint is streams for both. The previous allocation copied both configurations into radar/streams/stream.json, so one overwrote the other.

Each admitted stream now receives radar/<display>--<digest>/, retaining the existing stream.json, frames.npy and messages.bin leaf names. Display is the package-relative descriptor's parent name: each character outside ASCII letters, digits, underscore and hyphen becomes one underscore; truncate to 32 characters and use stream if empty. Digest is the full 64 lowercase SHA256 digits of the exact package-relative POSIX stream.json path encoded as UTF-8, without case or Unicode normalization. All derived directories are checked for case-insensitive duplicates before copying or decoding.

Consumers should follow the existing manifest artifact-path fields. The legacy source_id hint is preserved, including streams for these simulator entries; the exact copied descriptor and raw MCAP paths preserve the recorded source/stream identity. No metadata parser, new manifest field, geometry inference or numerical decoder change is introduced. Hardware-prefixed and legacy-layout hints retain their existing meaning. Artifact directory names change, including for noncolliding inputs.

The original witness on accepted issue 109 successor e29fecc46a55e1c5eb4c2a6919199d81a09512a0 used honestly authored typed MCAP data and the exact six-key simulator descriptor values, plus a hardware-naming control. It recorded 33 checks: 28 passed and five failed. Three descriptors yielded two artifact paths; the first simulator entry pointed to the second configuration's bytes. Three further failures bound the proposed deterministic directory rule. All source and raw bytes were preserved.

These canonical descriptors contain no top-level geometry. The witness therefore requires geometry:null and frames_npy:null and does not claim numerical array materialization, actual simulator execution, physical radar acquisition or hardware synchronization. The maintained protobuf/MCAP writer convention is exercised and its authored payloads round-trip through the real reader.

Scope is the additive naming helper, export_radar_mcaps allocation/preflight, the two Produces documentation lines, and dedicated tests/this guide. Existing admission and exclusion rules, source hints, manifest policy, decoder, preset registry/serialization, main/wizard, selected-clip work, issue 109 video implementation and other modalities remain unchanged. The preset owner's unresolved metadata is not treated as an ownership release. Native receiving and source storage do not imply hosted Actions, installation or live adoption.
