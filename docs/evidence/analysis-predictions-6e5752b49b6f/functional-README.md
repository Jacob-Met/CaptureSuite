## What the gate establishes

1. Actual QFileDialog choices preserve the returned path, including Unicode and a trailing native POSIX filename space. Cancellation retains the previous choice. Late real-dialog results are retired after explicit controller changes to mode, command, busy reservation, or package identity. Same-package refresh retains the path; a different package clears it while preserving external mode. Other commands omit prediction_path and retain their existing dependency/window values. Clear preserves external mode and gives the Choose control Qt focus.

2. Real workbench external jobs retain the exact selected bytes, source-bundle manifest and SHA-256 provenance. Predictions are aligned to the fixture's canonical source-window order without losing its integer timestamps or supplied values. Identity mode omits a previously retained path and produces the existing identity-teacher report. A source-hash mismatch produces the actual visible error and retained failed-job record, then choosing a valid second file allows a real successful retry.

3. A pass-through run observer pauses one real worker immediately before calling the unchanged evaluator. The already queued extra dictionary keeps its original dependency and path when the old dependency picker is changed through its editable Qt control. The new input widget is disabled both during reservation before thread start and during work. A deliberate receiver-authored replacement of the selected file at the same path is consumed and retained at execution. This qualifies path selection and execution-time byte binding; it does not claim that selecting a file freezes its bytes.

4. External mode with an empty path is blocked by an actionable native UI message. Deliberately bypassing that frontend validation and invoking the actual worker with the exact explicit-empty extra still fails as external input. It does not fall back to identity output.

The six jobs comprise three completed external runs, one completed identity run, one refused source binding, and one refused empty external path. Positive jobs retain their actual completed_with_warnings status and provisional fixture warnings. Every real evaluator call is forwarded once to the unchanged function; no scorer, worker, dialog result, output or error is stubbed.
