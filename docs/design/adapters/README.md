# Vendor Adapter Notes

Lab notes that turn [VENDOR_SPIKE.md](../VENDOR_SPIKE.md) measurements into adapter design inputs. They are not workers and not SDK bindings.

## Spike first

Do **not** wire a vendor SDK into the daemon or a CaptureSuite worker until sections 1–8 of the spike checklist are filled from a standalone console probe. A program that prints timestamped samples is enough. See [tools/vendor_spike/](../../../tools/vendor_spike/).

Milestone 6 covers the radar **family**, not one part number, and each radar class carries its own `data_schema_id`. The reasoning and the rules for adding a further board are in [../RADAR_PIPELINE.md](../RADAR_PIPELINE.md).

Dated lab fill-ins go under [notes/](notes/) (generated by `tools/vendor_spike/spike_checklist.py --write-notes`). Keep secrets out of this tree; Delsys credentials stay in Windows Credential Manager per [OPERATIONS.md](../OPERATIONS.md).

**Agent / human prompts:** copy [docs/prompts/01_vendor_spike.md](../../prompts/01_vendor_spike.md) into Cursor. After the spike, use [02_python_plugin.md](../../prompts/02_python_plugin.md) or [03_cpp_plugin.md](../../prompts/03_cpp_plugin.md) plus `tools/new_plugin.ps1`.
